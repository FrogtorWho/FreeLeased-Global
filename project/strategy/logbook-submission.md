## Part 1 · Level definitions (adapted to FreeLeased)

**1 — Idea / concept sketched**
The leasehold-governance thesis is articulated: leaseholders are structurally
outgunned on service charges, Right-to-Manage, and building-safety liability.
FreeLeased codifies UK + Caribbean statutes into a per-resident audit of hidden
rights that works offline, is resident-owned, and carries provenance on every cell.
*Exit criterion:* problem+solution statement names the legal domain (leasehold, not
general tenancy). ✅

**2 — Problem validated with 3+ conversations**
≥3 independent signals from real leaseholders/RTM directors confirming the pain:
unlawful service charges, missed s.20 consultation thresholds, BSA remediation
costs. Each tied to a specific statutory right. *Exit criterion:* 3 documented
statements from distinct real people. 🟡 Partial (founder's RTM case + advisory
letters exist; formal third-party interviews to be captured.)

**3 — Paper prototype / wireframe**
The end-to-end audit flow is designed: document ingestion → statutory diagnostics
→ per-resident hidden-rights report → action plan → resident sign-off, with
5-tuple provenance. *Exit criterion:* annotated wireframe of the journey exists.
✅ (the live 9-view application IS the realised prototype.)

**4 — Working prototype in the lab**
The deterministic engine runs on curated inputs: 9-jurisdiction statutory spine
(20+ codified rights), consensus/alignment gate, fairness scoring, veracity engine,
live API — all reproducible. *Exit criterion:* green verification run on synthetic-
labelled data, re-runnable on demand. ✅ (67/67 tests, live endpoints, tsc clean.)

**5 — Prototype tested with 1 real user**
One genuine leaseholder/RTM director (not the team) runs their own real documents
through the audit end-to-end and reaches a signed-off report. *Exit criterion:*
one recorded session with a real user, real redacted docs, feedback logged. 🟡 In
reach — Hudson House RTM pack identified; execution in progress.

**6 — Field pilot with a design partner**
An RTM company, leaseholder association, or advocacy org adopts the tool for a
real building, feeding real service-charge/lease data and acting on outputs.
*Exit criterion:* signed design-partner arrangement + ≥1 real building processed +
at least one action taken on findings. ⬜ MoU letters sent; no active pilot yet.

**7 — Reliable in a real environment**
Handles messy real-world inputs (scanned leases, inconsistent service-charge
accounts, multiple buildings) without hand-holding; PII redaction and provenance
behave correctly at small scale. *Exit criterion:* N buildings processed, low
error/abstention rate, no data-safety incidents. ⬜

**8 — Full feature set, small user base**
All core modules live for a real cohort: service-charge audit + RTM eligibility +
BSA compliance across UK, with ≥1 Caribbean jurisdiction on real data.
*Exit criterion:* modules used recurringly across ≥2 jurisdictions. ⬜

**9 — Paying users / launched**
Public launch of the OSS platform + a sustaining revenue path (hosted audits,
funded deployments, or association partnerships). *Exit criterion:* ≥1 paying/
committed customer with OSS core freely available. ⬜

**10 — Scaling with proven traction**
Multi-jurisdiction adoption with retention and outcome evidence — buildings taken
into RTM, charges recovered, safety issues escalated — and a repeatable onboarding
path for new jurisdictions. *Exit criterion:* sustained growth + documented
resident outcomes across jurisdictions. ⬜

## Part 2 · Self-assessment

**Where is the project today?**

Level **4→5** (reaching from lab into first real-user test)

**Note for the judge:**

FreeLeased is a deterministic statutory-diagnostics engine for leasehold
governance: it codifies 20 UK + Caribbean resident rights into auditable
diagnostic rules, runs a consensus/alignment gate as code (not prose), and
scores every finding through a veracity engine grounded in Popperian
falsifiability, NATO/Admiralty source grading, and ICD-203 calibrated
language. The engine is verified in-lab: 67/67 deterministic tests pass,
our-source TypeScript compiles clean, and live API endpoints return correct
shapes on synthetic-labelled data.

We are honest about where we are: **Level 4** (working prototype in the
lab), actively executing toward **Level 5** (first real user). The founder's
own RTM case (Hudson House) is the natural first real-user test and is in
progress — it will count for Level 5 only once the real pack is run through
the tool and evidenced in the Data Room.

Seven MoU letters to Caribbean government agencies (Barbados, Cayman,
Guyana, Belize, Jamaica, Trinidad) demonstrate regulatory receptivity and
pipeline toward Level 6, but no active field pilot is underway yet.

The statutory spine (9 jurisdictions, 20+ codified rights), the truth-
protocol verification engine, the consensus gate, and the 9-view
application are real, tested, and documented in the Data Room. Synthetic
pilot data is explicitly labelled as such. We do not claim levels we have
not earned.
