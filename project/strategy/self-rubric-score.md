## A1 · Architecture — **8.0 / 10**

The architecture is a 4-tier ladder: codified → RAG-agentic → consensus
→ human-in-the-loop. The 4 dossier agents (Resident Status, Tenure +
Building, Contracts, Hidden Rights) each emit a Dempster-Shafer belief
interval, and the consensus gate takes the weaker of two. That's not a
diagram I drew — it's the actual control flow in
[`src/lib/engines.ts`](engines.ts) and
[`src/lib/consensus.ts`](consensus.ts). The provenance chain-of-custody
on every datum is enforced at the type level. The reconcile-doc
runner reports 10/10 with zero drift, which means the architecture in
the docs matches the architecture in the code. **Residual risk:** the
architecture is a *spine* not a *showroom*. I haven't built the
swim-lane live view in the UI yet. The judge who skims the code will
see it; the judge who only watches the demo may not.

## A2 · Multi-agent design — **8.0 / 10**

There are 5 named agents in the production system
([`src/lib/agents.ts`](../../src/lib/agents.ts)): fl-craft-review,
fl-verify, fl-dataviz, fl-schema, fl-integrations. The 4 dossier
agents above are the *data path*; these 5 are the *team path*. Each
has a clear input/output contract and a separate DSP-5 trace. The
"agent team pattern" is the multi-agent demonstration, and the
governance layer is a 5-of-5 active-in-last-60s counter. **Residual
risk:** agent-to-agent coordination is *configured* but not
*showcased*. A judge who asks "show me two agents handing off a
task live" gets a configuration, not a demo. The product handles
this honestly — I have a sign-off queue and a consensus gate, both
visible — but the *coordination* moment isn't a default surface.

## A3 · Orchestration — **8.0 / 10**

The orchestration story is the consensus routing. Codified vs
agentic, three routes: surface, review, abstain. The 27/50 hitl-
required figure from the pilot is a real number — it's the
deliberate thinness of the data spine forcing the gate to escalate.
That ratio is honesty as an orchestration story. **Residual risk:**
the model-tier escalation (small → large on low confidence) is
*designed* but not wired in production. The Tier-2 RAG-agentic
fallback exists in the type system; the routing is not yet live.
This closes on the Tier-1 to Tier-2 router refinement, which is
the next big lift.

## A4 · HITL — **7.5 / 10**

This is Vince Fong's lowest score and the rubric axis most at risk
for the whole submission. The sign-off queue routes exist; the audit
trail is immutable; the appeal path is in the type system. The
[`src/pages/MobileCapture.tsx`](../../src/pages/MobileCapture.tsx)
file now ships a prominent Capture CTA and an `aria-live` region
so a screen-reader user hears every status change. The
*weakness* is that the live demo doesn't yet click-through to the
sign-off queue and show "this claim was reviewed, here's the
audit row, here's the appeal button" in a single 30-second beat.
That's a demo-pass lift, not a code lift. **Residual risk:** without
that single demo beat, A4 reads as "I promise HITL exists" rather
than "watch HITL work."

## A5 · Efficiency — **7.5 / 10**

The $0-compute claim is provable. 231 tests, deterministic rules,
local SQLite, no LLM in the resident-facing path. The
[`scripts/generate-sample-dossier.ts`](../../scripts/generate-sample-dossier.ts)
script is reproducible and shows the cost is genuinely $0.00.
**Residual risk:** I don't have an *Efficiency Panel* in the UI
yet. The numbers are real; the surface for the judge to see them is
not. This is a 1-day lift: surface a "tokens/task, % Tier-1
codified, cost per lease" panel. Romanow's axis closes on this
single panel.
