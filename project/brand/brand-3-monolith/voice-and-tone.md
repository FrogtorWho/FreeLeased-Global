# Voice & Tone — Monolith

## Three things we always do

1. **State the fact. State the next step. Stop.** Three-line max
   for any UI surface. No marketing prose.
2. **Use present tense, active voice, no hedging.** "The system
   rejected clause 4.b" — not "Clause 4.b was unfortunately
   identified as potentially problematic."
3. **Show the keyboard shortcut.** Monolith is a power-user
   brand. Every action has a shortcut. We name them.

## Three things we never do

1. **Never soften with adverbs.** "Very", "really", "just",
   "simply" are all banned. If it needs an adverb, the verb
   is wrong.
2. **Never apologize for being technical.** If a judge doesn't
   know what a "dossier" is, that's a learning moment, not
   something to cushion.
3. **Never use stock phrases.** "Cutting-edge", "next-generation",
   "AI-powered" are all banned. The product shows the work.

## Tone by surface

| Surface | Tone | Example |
|---|---|---|
| Marketing site | One-line announcement | "Provenance-tracked lease intelligence. $0 compute." |
| Product UI | Terminal log | "02:14 UTC · dossier #abc123 verified · 3 sources" |
| Error states | Terse diagnostic | "Error: page 4 unreadable. Action: re-upload." |
| Empty states | Single line | "Queue empty. 0 pending." |
| HITL queue | Audit log | "Reject · clause 4.b · s.27(3)(a) · 2m 14s" |
| Press | Changelog | "v0.9 — sign-off queue · 12 commits · 1 contributor" |

## What we sound like

A changelog. A status page. A well-written commit message. The
shortest path from "what happened" to "what to do next."

## Vocabulary do's and don'ts

| Use | Avoid |
|---|---|
| dossier, verdict, evidence | claim, score, rating |
| sign-off, decision, dispatch | approval, review |
| source, citation, statute | law, rule, regulation |
| verified, attested, declared | confirmed, validated |
| queue, batch, run | workflow, journey |
| 02:14 UTC | "earlier today" |
